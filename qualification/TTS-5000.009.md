## Conformance roles and features

| Role | Mandatory features | Optional or discretionary features |
| --- | --- | --- |
| Distribution producer | Exact UTF‑8 record grammar, hierarchy, address uniqueness, cross-field rules, complete line termination, and canonical filename | Any number of comments or data records; checksum and compression parameters may vary |
| Distribution consumer | Streaming validation of comments and entries, exact hierarchy and field rejection, and collected address/key index | Empty distribution; comments and assigned interest flags may be ignored after parsing |
| Segment producer | Same record and hierarchy rules with an explicit initial domain, zone, and local-net context | Zone, Region, Host, and Hub segment forms |
| Segment consumer | Streaming validation from the explicit context and rejection of empty, mismatched, or context-free segments | Zone, Region, Host, and Hub segment forms |
| Publication producer | Exact text and `.zst` names and one dictionary-free ordinary Zstandard frame | Checksum may be present or absent; compression parameters may vary |
| Publication consumer | One-frame Zstandard decoding and rejection of dictionaries, skippable frames, concatenation, trailing data, truncation, and malformed decompressed text | Checksum may be present or absent |
| Hierarchy and assertion observer | Typed branch membership, coordinator scopes, node state, contact state, flags, IIH service, and current authoritative key assertion | Any assigned coordinator or contact assertion may be absent |
| Key resolver | IIH key for the exact non-anonymous address and no key where none is published | Endpointless IIH remains a key assertion |
| Node operator | Current `DDD-nodelist.zst` FileRequest name and a demonstrated configured byte-exact response | The availability statement is a SHOULD and permits a justified local exception |

Private keyword extensions and legacy input tolerance are not optional native
features. A conforming TTS‑5000 parser rejects them.

## Security review

The untrusted boundaries are the compressed publication bytes, decompressed
UTF‑8 records, externally supplied segment context, and application
provenance supplied to the producer. The reader consumes through `BufRead`
without a fixed protocol limit, requires a terminating LF before parsing a
line, validates UTF‑8 before scalar inspection, rejects every prohibited
control, requires eleven fields, and stops permanently after the first error.
I/O failure is reported without returning a partially accepted record.
Allocation failure, platform overflow, and local resource policy remain host
failures rather than alternate accepted encodings.

The Zstandard wrapper checks the ordinary-frame magic before constructing the
decoder, requests one frame, and rejects every byte remaining after that
frame. The pinned external decoder rejects malformed and dictionary-dependent
frames. Compression and decompression stream through caller-provided I/O, so
the TITH wrapper adds no hidden output-size limit or whole-publication buffer.
Callers must still apply local storage and decompression resource policy; an
allocation or sink failure is propagated and cannot produce an accepted
partial nodelist.

Hierarchy state begins from either no active Zone or one explicitly validated
segment context. Each transition clears lower-tier state, Hub requires Host,
Pvt requires a local net, Region and Host share the address namespace, and an
address set rejects every collision. Coordinator assertions are recorded in
their exact Zone, Region, or net scope and reject a duplicate or invalid
placement rather than selecting one. The flat-file order therefore cannot
silently move a node into an undefined branch.

Contact state is derived only from a validated phone, a TTS‑5001-resolved
server-and-port pair, or an addressed email method. Bare defaults,
endpointless keys, and incomplete endpoints cannot accidentally make a Pvt
node contactable. Conversely, a usable target cannot be hidden behind Pvt.
Hold and Down are distinct states and do not reuse the contact invariant.

An IIH key is parsed by the qualified TTS‑5001/TTS‑0004 surface and returned
only for its exact address. The nodelist module does not authenticate a
publication or silently create a local pin; only a nodelist already accepted
as authoritative supplies the TTS‑0008 external anchor. SignedOrigin cannot
override an available Origin key. For first publication from an anonymous
application, the producer compares the exact 32-byte application key with
the IIH key and refuses a mismatch before writing the line.

The current-file integration test invokes a separately configured request
processor, chooses the current timestamped publication, and compares the
returned bytes exactly. That boundary neither makes legacy request syntax
part of the nodelist nor lets the standard infer publication authenticity.
Legacy conversion remains in its explicit adapter and native parsing does not
repair or preserve legacy forms.

Applicable malformed input, truncation, framing, I/O, hierarchy, contact,
address, flag, key, and provenance paths are covered by the negative tests in
the matrix and complete branch coverage.
