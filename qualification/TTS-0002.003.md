## Conformance roles and features

| Role | Mandatory and recommended features | Optional features |
| --- | --- | --- |
| Type/Length producer | Canonical shortest-form non-negative integer production, including zero | None |
| Type/Length consumer | Canonical prefix consumption and rejection; at least the complete 32‑bit range, with the recommended 63‑bit range also implemented | None |

The reference implementation supports the complete unsigned 64‑bit range,
which exceeds both documented width requirements. TTS‑0002 defines no named
optional capability, syntax, operation, or protocol path.

TTS‑0002 owns the unsigned integer representation used for Type and Length.
The generic TLV container code consumes that representation but also owns I/O,
Value boundaries, and the TTS‑0003 Type‑0 rule. It is therefore an integration
witness rather than part of the TTS‑0002 conformance surface. The TTS‑0007
signed mapping likewise consumes this codec from a separate source module.

## Security review

Type and Length integers are unauthenticated framing input. The decoder reads
from a borrowed slice and allocates nothing. It rejects an empty input, a
redundant leading zero group, a missing terminal byte, and a value outside its
supported range. Accumulation checks multiplication before shifting the prior
value; after that succeeds, the product is at most `u64::MAX − 127`, so adding
the next seven-bit digit cannot overflow. No path truncates or wraps a value.

The prefix decoder stops exactly after the first byte whose continuation bit is
zero and reports how many bytes it consumed. The bounded convenience decoder
rejects any trailing byte. Generic TLV integration tests demonstrate that the
same rejection occurs in both Type and Length positions. Interpretation of a
decoded Length, Value truncation, allocation for a Value, I/O failure, and the
invalid Type‑0 rule belong to the carrying TLV and common-type standards, not
to this integer representation.

The producer accepts a fixed-width `u64`, uses a ten-byte stack buffer, and
allocates at most ten output bytes. Its allocation size is therefore not
controlled by untrusted input and has no meaningful resource-failure
conformance case. There is no persistence, concurrency, or recovery behavior.
