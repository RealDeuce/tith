## Conformance roles and features

| Role | Mandatory features | Optional or conditional features |
| --- | --- | --- |
| Profile implementer | Exact successful outputs, input acceptance and rejection, constants, structures, operation order, and failure results of the pinned source | A different implementation or safe wrapper may be used if results remain interchangeable |
| Generic-hash implementation | One-shot and streaming unkeyed hashing, exact context and input bytes, and zero-length state finalization | Required when selected by a calling TITH document |

| Signature verifier | Exact verification result and no action on unauthenticated output | Required when selected by a calling TITH document |
| KK initiator and responder | Static KK packet processing, transcript finalization, session-key agreement, authentication failure, and opposite-role interoperability | Required when selected by a calling TITH document |
| Secretbox sender and receiver | Exact ciphertext and plaintext behavior, message identifier, context, and authentication failure | Required when selected by a calling TITH document |

including every conditional feature. It uses a private safe Rust wrapper over
the pinned C source; use of that source is not a conformance requirement.

## Security review

The trust boundary is the private FFI between safe Rust and one immutable C
source tree. `tith-crypto` remains the only portable crate permitted to cross
it. The ABI declares only the used Version 1 surface, asserts structure sizes
and alignments at compile time, checks Rust-to-C length conversions, initializes
output only after a successful call, and erases secret-key bytes on drop.

The principal wire threat is an attacker-controlled signature, KK packet, or
secretbox ciphertext. Verification, key exchange, and decryption errors return
typed failures and expose no authenticated output. Mutation and wrong-context,
wrong-key, wrong-identifier, wrong-state, and malformed-length tests enforce
those boundaries. The reference implementation never negotiates or falls back
to the broken source behavior.

The supply-chain boundary is the vendored snapshot. The provenance record pins
both commit and Git tree; the complete manifest detects modified, missing, and
additional files on Ubuntu, Windows, and locally. `.gitattributes` prevents
checkout newline conversion within the snapshot. The snapshot remains an
external dependency and contains no TITH-specific patch.

The zero-output-finalization rule is security critical because a silent early
return changes the KK transcript state while internally matched peers still
appear to work. The direct finalization test, fixed external responder packet,
opposite raw/safe roles, and independent C fixture make that failure visible.
The fixed vectors contain no production secret; generated keys and randomness
continue to come from the pinned implementation.
