## Conformance roles and features

| Role | Mandatory and recommended features | Optional features |
| --- | --- | --- |
| Signed-integer producer | Map each supported signed value to its unique non-negative value and emit the canonical TTS‑0002 representation; support at least the complete 32‑bit range | None |
| Signed-integer consumer | Reject every invalid TTS‑0002 representation and every value outside the supported signed range; apply the even/odd inverse mapping; support at least the complete 32‑bit range and preferably the complete 63‑bit range | None |

The reference implementation supports the complete signed 64‑bit range,
which exceeds both documented width requirements. TTS‑0007 defines no named
optional capability, syntax, operation, or protocol path.

Downstream item formats may select this representation for their fields, but
they own those fields' types, units, placement, and cardinality. They are not
dependencies or part of the TTS‑0007 conformance surface.

The implementation supports every `i64`. Every `u64` is either even and maps
to `0..=i64::MAX`, or odd and maps to `i64::MIN..=−1`; the two cases are
disjoint. The inverse producer branches recover the original even or odd
`u64`. TTS‑0002 canonicality then supplies the one byte string for that mapped
value.

## Security review

Signed integers may be unauthenticated item data. The decoder reads a borrowed
slice and allocates nothing. Its first operation is the qualified bounded
TTS‑0002 decoder, so empty, nonminimal, unterminated, trailing, and overflowing
unsigned inputs fail before signed interpretation. No invalid representation
is repaired or accepted.

For every accepted `u64`, division by two is at most `i64::MAX`, so converting
that quotient to `i64` cannot wrap. An even value returns the nonnegative
quotient. An odd value returns its negation minus one; at `u64::MAX` that is
exactly `i64::MIN`, without evaluating the overflowing expression `U + 1`.

The producer's nonnegative input is at most `i64::MAX`, so doubling its
unsigned value is at most `u64::MAX − 1`. A negative input's unsigned
magnitude is at most 2^63; subtracting one before doubling and adding one is
therefore at most `u64::MAX`. No producer or consumer path truncates, wraps,
or takes the overflowing signed absolute value of `i64::MIN`.

The producer delegates to TTS‑0002's encoder, whose allocation is bounded by
ten bytes. The decoder's work is bounded by that codec's maximum accepted
width. There is no persistence, concurrency, recovery, secret material, or
input-dependent unbounded resource behavior in this standard's surface.
