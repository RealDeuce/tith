## Security review

The untrusted boundary is every flag-list string and every public constructor
value supplied to the standalone API. A validated list can be constructed
only by parsing the exact canonical text or by re-parsing the formatted typed
values. Every parser rejects empty members, alternate case, misplaced names,
wrong order, duplicate values, prohibited arguments, and invalid scalar
boundaries before returning the list.

Server strings receive exact DNS, IPv4, or bracketed canonical-IPv6 checks.
No normalization can collapse two external spellings into one typed endpoint.
Ports reject zero, overflow, signs, whitespace, and leading zeros, and the
numeric DNS-server and explicit-port forms remain distinct. Default expansion
copies every INA value in preference order without changing an explicitly
addressed occurrence. Endpoint usability requires both a server and a port;
the absence of an assigned TITH port therefore cannot silently select one.

An IIH public key must be exactly 43 standard-alphabet unpadded RFC‑4648
characters, decode canonically to exactly 32 bytes, and match every other IIH
key in the list. The typed key is the qualified TTS‑0004 value. Parsing a key
records a nodelist assertion only: this module neither establishes a local pin
nor authenticates a peer, and the underlying service operation is expressly
outside TTS‑5001.

Email addresses preserve their Unicode scalar values byte-for-byte. Empty
explicit addresses, C0 controls, U+007F, and Comma are rejected; no address is
inferred, repaired, or normalized. Resolution expands all addressed IEM
values in their stated preference order, ignores a bare IEM as a default, and
never lets one explicit method address affect another occurrence.

The Other extension grammar is bounded to 32 ASCII alphanumeric characters,
sorted after all assigned names, and cannot disguise a name assigned in any
category. The public extension constructor checks all five assigned
registries, including every Other Flag. Case remains significant, so exact
`TRACE` is assigned while `trace`, `TRACEX`, `V32B`, and `V42B` remain
unassigned extensions. Applicable failure paths are
covered by the negative tests in the matrix and complete branch coverage.
TTS‑5001 defines no persistent state, concurrent ownership, framing length,
cryptographic operation, or facility-operation failure behavior of its own.
