parser limit: producers can build the recommended one- or two-payload layout,
and consumers accept any number of valid payload SignedTLVs. Every named
optional or conditional path above is implemented.

## Security review

Authenticated Rejected input remains a reviewed boundary. Type and
Length bound both reason and description before interpretation. The
parser rejects malformed children, unsupported reason numbers, duplicate
fields, prohibited placement, and the former raw grammar. No fallback
parser can reinterpret the same bytes under a second format. Tests cover
a reason Value of 5, strings containing type bytes, every optional-field
state, and unknown extensions at every boundary.


Unauthenticated bytes first cross canonical TTS‑0002/TTS‑0003 framing. The
Bundle parser requires the literal Origin, adjacent conditional keys, exact
Header grammar, and exact Header hash before payload contents are classified.
Malformed framing stops at the failing offset; malformed or unauthenticated
SignedTLV data is never exposed as accepted work. Unknown values cannot satisfy
assigned requirements or split an adjacent address/key pair.

A non-anonymous key supplied on the wire cannot override TTS‑0008 resolution.
The sole exception is the dedicated PublicKeyRequest reply, whose complete
shape, reversed identities, request identifier, payload hash, advertised key,
Accepted successor, and signature are checked together. A predecessor proof is
accepted only under the exact requested key. A self-signed first-contact result
is merely an observation until the exact contact is locally authorized.
Failure under the requested predecessor does not fall back to the current key
or create trust evidence.

RequestIdentifier alone is not authority. Every response is bound to the exact
encoded request SignedTLV by TLVHash, and completion records the pair. Equal
identifiers in different payloads or directions remain distinct. Duplicate,
unexpected, unauthenticated, and incomplete responses fail; the Client
completes from authenticated outstanding-response accounting and does not wait
for Server FIN.

Poll selection occurs in one redb write transaction. It claims every matching
unclaimed copy or none if the set is empty, scopes anonymous work by exact key,
and leaves active or later work outside the snapshot. Errors while building a
reply release every claimed copy, as exercised by the daemon fault path.

Acceptance validates carrier kind, authentication state, and stable signed
identity before one transaction writes the item, record, and duplicate index.
A duplicate lookup returns the earlier durable identifier and does not create
another item. Records have no automatic expiry; explicit removal is separately
tested. Store failure is not converted to Accepted, so responsibility remains
with the sender.

Fixed-size hashes and keys reject other lengths. Hashing and signature native
failures propagate as local errors. Persistent operations use checked
transactions; malformed carrier combinations, wrong request correlation,
wrong signer, and interrupted exchange states fail closed. The implementation
introduces no arbitrary Bundle or payload size limit.
