## Security review

Untrusted bytes cross the boundary through canonical TLV framing before item
grammar validation. Literal leading children, adjacent anonymous keys,
assigned-type ordering, cardinality, canonical integers and addresses, UTF‑8,
nested lengths, and prohibited combinations are checked before a value is
acted on. Unknown values are retained but never satisfy a known requirement.

SignedData is verified over the exact received child encodings through the
byte before Signature. Origin receives one effective key from the using
context. If that key exists, failure is terminal for that signer and never
falls back to SignedOrigin. SignedOrigin is used only when Origin has no key;
anonymous signers require their adjacent exact key. Cryptographic operation
failures propagate as local errors rather than becoming authentication
results. Tests cover every valid/invalid/unsigned outcome and that failure
propagation.

Stable duplicate identity is exposed only after successful verification and
includes the canonical kind, exact signer identity, and Signature. Mutable
request/routing suffixes are excluded. Forwarding preserves every signed byte
and Signature and only appends suffix data. Embedded Files cannot smuggle an
independent provenance. FileRequests have only transport authentication.

Reserialization retains unknown values and signed bytes exactly. A retained
signature which does not verify under its recorded signer is refused. The
adapter's byte-exact self-check prevents a legacy presentation from silently
becoming a different authenticated item; ordinary legacy input is explicitly
minted as a new canonical item. Filename path components are rejected, while
the exact portability list is producer guidance rather than a consumer
interoperability ban. Replaces policy and candidate selection remain local and
cannot authorize deletion merely by matching a pattern.
